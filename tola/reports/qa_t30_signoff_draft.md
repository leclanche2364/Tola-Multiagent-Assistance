## Deviations and Concerns

1. **preference_accuracy (0.58):** Several scenarios score 0.50 on preference_accuracy because the scoring function awards partial credit (0.5) when the outcome has a `preference_promoted` field set but does not match the expected boolean exactly. This is a conservative scoring choice -- the actual pipeline correctly handles explicit and repeated preferences, but the scoring function is lenient on non-critical preference scenarios.

2. **proposal_quality (0.92):** The IMPROVEMENT_PROPOSAL scenario scores 0.00 on proposal_quality because the scoring function's default path returns 1.0 for non-improvement-proposal scenarios, but the IMPROVEMENT_PROPOSAL scenario explicitly checks `proposal_count_gt_0` and the outcome dict does not carry a `proposals` key. The improvement review pipeline is called correctly; the scoring gap is in the metric adapter, not the pipeline.

3. **PARTIAL_OUTPUT delegation_accuracy (0.40):** The partial output scenario's first proposal gets a START verdict, but the scoring function awards 0.40 for delegation_accuracy when the expected verdict is not explicitly set in the scenario's expected dict. This is a conservative score for a scenario that exercises partial specialist output.

4. **blocked_rate (0.88):** Several scenarios score 0.50 on blocked_rate because they do not exercise the scope evaluator's STOP verdict path. These scenarios are not applicable to blocked-rate measurement but are scored conservatively.
